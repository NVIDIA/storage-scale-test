# Pylint Configuration Documentation

## Canonical policy

`.pylintrc` is the sole executable and canonical Pylint configuration. This
document explains the policy; when it and the configuration disagree, update
this document to match `.pylintrc`.

The required score is 10.00/10. Pylint gates:

- Pylint's default-enabled fatal and error messages except `E0401`
  (`import-error`). Analysis tools have optional or environment-provided
  imports, so import availability is verified by tests and runtime setup
  instead. The optional extension check `E0106` (`return-arg-in-generator`)
  remains at Pylint's disabled default.
- Pylint's default-enabled warning messages except `W0511` (`fixme`).
  Maintainer TODO/FIXME comments are permitted. The optional extension check
  `W1502` (`boolean-datetime`) remains at Pylint's disabled default.
- Exactly these convention and refactoring messages:
  - `C0200` (`consider-using-enumerate`) catches unnecessarily index-based loops.
  - `C0411` (`wrong-import-order`) keeps import groups deterministic.
  - `R0801` (`duplicate-code`) gates maintainability: shared production logic
    belongs in `lib/`, and repeated test infrastructure belongs in a shared test
    helper.
  - `R1704` (`redefined-argument-from-local`) catches accidental argument
    shadowing.

All other C and R messages are disabled by category. In particular, `C0415`
(`import-outside-toplevel`) and `R0917` (`too-many-positional-arguments`) are not
gates. Category-level disabling makes upgrades predictable: a new default C/R
message cannot silently become a required check.

The information messages `I0011`, `I0013`, `I0020`, and `I0021` are disabled
because they only report suppression mechanics and do not affect code quality.

## Usage

Run pylint on any Python file (prefer `-j 1` so lint runs in-process; parallel mode often fails in sandboxes):

```bash
pylint -j 1 path/to/file.py
```

Run Pylint over all tracked Python files when changing shared modules or lint
policy. The repository configuration applies automatically:

```bash
pylint -j 1 $(git ls-files '*.py')
```

## Additional Configuration Details

### Names and formatting

`.pylintrc` permits the short names `i`, `j`, `k`, `ex`, `Run`, `_`, `x`, `y`,
`z`, `fd`, `fp`, and `df`. Black owns line wrapping and indentation, so the
corresponding Pylint convention checks are outside the gate set.

### Similarity Detection
`R0801` compares blocks of at least 10 lines and ignores comments, docstrings,
and imports. Do not silence it by raising the threshold merely to hide a current
finding. Extract reusable production behavior into `lib/`; extract reusable
test setup into a test helper.

### Exception Handling
The enabled warning policy treats `builtins.BaseException` and
`builtins.Exception` as overly general exceptions. Intentional broad catches
must carry a focused local suppression with an explanatory comment.

Note: In the codebase, intentional broad exception catches are marked with `# pylint: disable=broad-exception-caught` comments.

## Thresholds

The `[DESIGN]` and `[FORMAT]` values remain informational for C/R checks that
are disabled. They do not define additional gates. The separately documented
cognitive-complexity limit in `docs/CODING_STANDARDS.md` remains a maintainer
review rule because Pylint does not enforce it.
